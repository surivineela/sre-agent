# Feature Rubric

Human evaluation for feature implementation tasks. Score each metric 1-5.

---

## Scoring Scale

| Score | Meaning |
|-------|--------|
| 5 | Excellent — exceeds expectations, no issues |
| 4 | Good — meets expectations, minor issues only |
| 3 | Acceptable — works but has notable gaps |
| 2 | Poor — partially works, significant issues |
| 1 | Failing — does not work or missing entirely |

---

## Metrics

| Metric | Score (1-5) | Notes |
|--------|-------------|-------|
| **Planning** — Clear plan created before implementation, identifies files to modify, breaks down work into logical steps. Dock points whenever planning needs adjustments. | | |
| **Correctness** — All requirements implemented, no bugs introduced | | |
| **Repo Alignment** — Follows existing patterns, conventions, file structure | | |
| **Test Coverage** — Tests added for new functionality, cover happy path and edge cases | | |
| **Code Quality** — Readable, maintainable, no dead code or artifacts | | |
| **Scope Discipline** — Changes focused, no unrelated modifications or scope creep | | |
| **AI Review** — What AI thinks of the code. Not considered heavily, but good to record | | |
| **Overall** — Subjective overall score | | |

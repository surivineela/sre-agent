## 🧭 DNS Diagnostic Workflow

### 🔹 Step 1: Check if Custom DNS Server configured or not
- Use tool `CheckIfCustomDNSConfigured` to check if there are any custom DNS servers configured for the container app environment or not
- If custom DNS servers are configured, then additionally call `GetCustomDNSServers` tool to get the list of custom DNS servers configured for the container app environment at start and end of time window.
    - Notify user about change in custom DNS servers if any.
- Else, proceed to next step highlighting no custom DNS server configured.

### 🔹 Step 3: Remediation Guidance

Based on findings, recommend:

- ✅ Validate health of custom DNS servers.
- ✅ Investigate CoreDNS pod health.
- ✅ Analyze upstream DNS server health.
- ✅ Suggest restarting CoreDNS pods as a mitigation step if issues persist with DNS resolution or CoreDNS pod health.
- ✅ Optionally suggest disabling fallback to Azure DNS for intermittent resolution issues ONLY if issue is about getting inconsistent DNS resolutions and custom DNS severs are configured.

To disable fallback:
```powershell
Set-ManagedClusterCustomHelmValues `
  -Name <managed-cluster-name> `
  -UpgradeChart `
  -CustomHelmValues '{"removeAzureDnsFallbackForApps": "true"}' `
  -Region <region>
```
- After sharing:  
  `NotifyUser("✅ Based on our findings, here are the recommended next steps: [summary].")`

## Enovy issue Diagnosis Process Workflow

### Step 0: Parameter Collection
Collect the following inputs:
- `fromDate` (Required)
- `toDate` (Required)
- `region` (Required) — convert to lowercase and remove spaces before tool use (e.g., `"francecentral"`)
- `containerAppName` (Required)
- `resourceGroupName` (Required)
- `subscriptionId` (Required) 
If any of these parameters are missing, use the `AskUserForInput` tool to ask the user for the missing parameters.

### Step 1: Use the `GetContainerAppManagedCluster` tool to fetch the Managed Cluster name of the Container App.
- If the tool returns the managedClusterName, use the `NotifyUser` tool to notify the user with the Managed Cluster name in the format: `"Managed Cluster name found: [managedClusterName]"`
- If the tool does not return the managedClusterName, use the `NotifyUser` tool to notify the user: `"Error fetching Managed Cluster name: [error message]"`. Then, use the `AskUserForInput` tool to ask the user for the Managed Cluster name.
Do not procced with the workflow if the Managed Cluster name is not found. You will need to use the `managedClusterName` as the input parameter in the next steps. 

### Step 2: Use the `GetEnvoyAbnormalLogs` tool to fetch Envoy Abnormal Logs.
Only when you retrieved the `region`,`fromDate`, `toDate`, and `managedClusterName` parameters, you can execute the `GetEnvoyAbnormalLogs` tool.
- If the `GetEnvoyAbnormalLogs` tool returns no logs, use the `NotifyUser` tool to notify the user: `"No Envoy Abnormal Logs found for the specified time range."`
- If abnormal logs are found, summary the log and use the `NotifyUser` tool to notify the user with the summary of the logs in the format: `"Envoy Abnormal Logs found: [summary of the logs]"`

### Step 3: Use the `GetEnvoyControllerLogs` tool to fetch Envoy Controller Logs.
- You should first check if the tool returns any error message. If there is, use the `NotifyUser` tool to notify the user: `"Envoy Controller Errors found: [summary of the errors]"`
- Summarize the log and use the `NotifyUser` tool to notify the user with the summary of the logs in the format: `"Envoy Controller Logs summary: [summary of the logs]"`

### Step 4: Use the `GetSwiftNetworkingEvents` tool to fetch Swift Networking Events.
- You should first check if the tool returns any error message. If there is, use the `NotifyUser` tool to notify the user: `"Swift Networking Errors found: [summary of the errors]"`
- Summarize the log and use the `NotifyUser` tool to notify the user with the summary of the logs in the format: `"Swift Networking Events summary: [summary of the logs]"`
- If the tool returns no logs, use the `NotifyUser` tool to notify the user: `"No Swift Networking Events found for the specified time range."`

### Stet 6: Use the `GetContainerAppAdminEvents` tool to fetch Container App Admin Events.
- You should first check if the tool returns any error message. If there is, use the `NotifyUser` tool to notify the user: `"Container App Admin Events Errors found: [summary of the errors]"`
- Summarize the log and use the `NotifyUser` tool to notify the user with the summary of the logs in the format: `"Container App Admin Events summary: [summary of the logs]"`
- If the tool returns no logs, use the `NotifyUser` tool to notify the user: `"No Container App Admin Events found for the specified time range."`

### Step 7: Use the `GetEnvoyPodStatus`, `GetEnvoyControllerPodStatus` and `GetContainerAppStatus` tools to fetch Envoy Pod Status, Envoy Controller Pod Status and Container App Status.
- Summarize the log and use the `NotifyUser` tool to notify the user with the summary of the logs in the format: `"Envoy Pod Status summary: [summary of the logs]"`
- Summarize the log and use the `NotifyUser` tool to notify the user with the summary of the logs in the format: `"Envoy Controller Pod Status summary: [summary of the logs]"`
- Summarize the log and use the `NotifyUser` tool to notify the user with the summary of the logs in the format: `"Container App Status summary: [summary of the logs]"`

### Step 8: Use the `GetEnvoyAccessLogs` tool to fetch Envoy Access Logs.
- If the time range between `fromDate` and `toDate` is more than 6 hour, use the `AskUserForInput` tool to notify the user: `"The time range is too large. Please narrow it down to 1 hour or less."`, and ask for a new time range. Continue the workflow with the new time range, if provided.
- Split the the `fromDate` and `toDate` into 1 hour intervals and use the `GetEnvoyAccessLogs` tool to fetch Envoy Access Logs for each interval. Summarize the logs and notify the user in the following way:
    - First check the HTTP response status of the access logs. Especially if the status is `4xx` or `5xx`, use the `NotifyUser` tool to notify the user: `"Envoy Access Logs Errors found: [summary of the errors]"`
    - Check the Request Duration, if the access request is taking much longer time than other requests, use the `NotifyUser` tool to notify the user.
    - If all the logs are normal, use the `NotifyUser` tool to notify the user that nothing abnormal was found in the logs.

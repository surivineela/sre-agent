### Step 2: Retrieve and Analyze Envoy Access Logs
- Step 2.0 : The provided 'fromDate' and 'toDate' may cover a large time range, so you will first plot the Envoy Access Request Count By Response Status as a time-series chart to help the user narrow down the time range.
   - Use the `GetEnvoyAccessRequestCountTimeSeries` tool to retrieve the Envoy Access Request Count data, grouped by response status.
   - Use the `NotifyUser` tool to notify the user: `"I am rendering the Envoy Access Request Count By Response Status as a time-series chart, it may take a while, please stay tuned."`
   - Use the `PlotTimeSeriesData` tool to present the Envoy Access Request Count grouped by Response Status as a time-series chart.
     **Ensure that every time point returned by the GetEnvoyAccessRequestCountTimeSeries tool is plotted, including those with a count of zero.**
     **Never aggreage, omit, or interpolate date points, especially for those timestamped entries that have a count of zero.**
   - Use the `NotifyUser` tool to notify the user with the chart in the format: `"Envoy Access Request Count By Response Status Over Time: [chart]"`
- Step 2.1: Verify the `fromDate` and `toDate` parameters.
  Ensure that you have already plotted the Envoy Access Request Count By Response Status as a time-series chart before proceeding with the next steps.
  - If the time range between `fromDate` and `toDate` is more than 3 hours, use the `AskUserForInput` tool to notify the user: `"The time range is too large. Please narrow it down to 3 hours or less."`, and ask for a new time range.
  - Once the user provides a new time range, continue the workflow using the updated time range.
- Step 2.2: Use the `GetEnvoyAccessLogs` tool to fetch Envoy Access Logs.
  - If the tool returns no access logs, it indicates there are potential issues with the Envoy component or load balancer. You must:
    1. Use the `NotifyUser` tool to notify the user: `"No Envoy Access Logs found for the specified time range. I am checking the Envoy component healthy status."`
    2. Go to the **Step 3** to continue the investigation.
  - If the tool returns access logs, it indicatest that the Envoy component is working properly. You must:
    1. Summarize the logs and use the `NotifyUser` tool to notify the user: `"Envoy Access Logs found: [summary of the logs]"`
         - For those requests with 'Status' in 5xx range, provide a detailed description of the access logs, including FirstSeen, LastSeen, RequestDuration, Count, Authority, Method, Path, Protocol, Status, ResponseCodeDetails, UpstreamHost.
         - For those requests with 'Status' smaller than 5xx, provide a brief description of the access logs, including FirstSeen, LastSeen, Count and Status, ResponseCodeDetails.
    2. Go to **Step 2.3** to analyze the access logs.
- Step 2.3: Analyze the access logs:
  Focus Areas: `ResponseCodeDetails`, `UpstreamHost` and `Status`.
  - If there is no requests with 'Status' in 0 or 4xx or 5xx range and all requests UpstreamHost is via_upstream, use the `NotifyUser` tool to notify the user: `"No requests with 'Status' in 0 or 4xx or 5xx range found. No issue found in access log."` Go to **Summarize all your findings**.
  - If `ResponseCodeDetails` contains the keyword `upstream`, this indicates that the Envoy component successfully forwarded the request to the upstream component. Next, examine the `UpstreamHost` field:
     - If the port is '4045' and status is not successful code:
       **Description and Suggestion**: `"The requests were forwarded to the 'Activator' component, as indicated by the upstream host port 4045. This suggests that the customer's application code was not scaled or did not start yet. Please verify activator status and the health and readiness status of the customer's application code."`
     - If the port is '1601' and status is not successful code:
       **Description and Suggestion**: `"The requests were forwarded to the 'EasyAuth' component, as indicated by the upstream host port 1601. This suggests that easy auth side car has some issue, and should check easy auth side car log."`
     - If the port is not '4045', this indicates that the Envoy component successfully forwarded the request to the customer's application code, and the request was handled by that code. Next, examine the `Status` field:
       - If the response `Status` is in the 5xx range:
         **Description and Suggestion**: `"The requests were handled by the customer's application code but returned an HTTP [Status], indicating that the customer code failed to process the requests successfully. Please advise the customer to check their application logs for further investigation."`
       - If the response `Status` is not in the 5xx range:
         **Description and Suggestion**: `"The requests were handled by the customer's application code and returned an HTTP [Status], indicating that the request was successfully processed by the application."`
  - If `ResponseCodeDetails` contains the keyword `downstream`, it indicates a client-side issue.
    **Description and Suggestion**: `"The requests returned [ResponseCodeDetails], which suggests a downstream issue—commonly associated with client-side problems like client side timeout is shorter than the time needed by server side to process the request. Please advise the customer to review their client logs for further investigation."
  - If `ResponseCodeDetails` does not contain upstream or downstream, it indicates an issue that may not be directly related to either the client or upstream components.
    **Description and Suggestion**: `"Some requests returned [ResponseCodeDetails], which may indicate a problem unrelated to the client or upstream services. Proceeding with further investigation into potential issues within underlying network infrastructure."`
- Step 2.4: Used the "NotifyUser" tool to notify the user in a **well-formatted markdown** including comprehensive descriptions and suggestions of the access log analysis result.
- Step 2.5: Go to **Step 4** to continue the investigation.

### Step 3: Check Envoy Component Healthy Status
- Step 3.1: Use the `GetEnvoyPodLogs` tool to fetch Envoy Pod Logs.
  Only when you retrieved the `region`,`fromDate`, `toDate`, and `managedClusterName` parameters, you can execute the `GetEnvoyPodLogs` tool.
  - If the `GetEnvoyPodLogs` tool returns no logs, use the `NotifyUser` tool to notify the user: `"No Envoy Pod Logs found for the specified time range."`
  - If envoy pod logs are found, summary the log and use the `NotifyUser` tool to notify the user with the summary of the logs in the format: `"Envoy Pod Logs found: [summary of the logs]"`
- Step 3.2: Use the `GetEnvoyControllerLogs` tool to fetch Envoy Controller Logs.

- Step 3.3: Use the `GetEnvoyPodStatus` tools to fetch Envoy Pod Status and Envoy Controller Pod Status
  Summarize the log and use the `NotifyUser` tool to notify the user with the summary of the logs in the format: `"Envoy Pods Status summary: [summary of the logs]"`

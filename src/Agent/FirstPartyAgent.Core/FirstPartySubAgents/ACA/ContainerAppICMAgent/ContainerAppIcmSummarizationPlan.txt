# Objective
You will be provided with the ICM `details` (nested JSON object) and optionally `comments` (JSON objects array) in a JSON string.
Your task is to extract the required information from the `details.summary` and `comments[].Text` text fields and present it in the markdown response template below without having unnessary newline or other white-spaces.

Any information present in the ICM must be included in the response.
If any information does not fit well into the predefined categories, place it in the `Additional Information` section. Ensure that no important information is omitted.

## 🧭 ICM Summarization Workflow

You must follow these steps to complete the task:

### 🔹 Step 1: Validate the given input
- Ensure the input is a valid JSON object and is not null or empty. The `details` object must be present in the input JSON, otherwise, return an error message like "Looks like incident is not valid".

### 🔹 Step 2: Extract the time window to debug the issue

- **Purpose:**  
    - Retrieve the provided time window to debug the issue or calculate it with the provided information.

- **How to proceed:**
Obtain the following details:

    - **fromDate**: `<Start time of the issue in UTC format>`
    - **toDate**: `<Resolution time of the issue in UTC format>`

    > *Note*: If only a single issue observed date is specified, denote it as `issueObservedDate` in the mentioned date format. Then, calculate:

    - `fromDate (calculated)` = Minimum of (issueObservedDate - 10 days, current date - 10 days)
    - `toDate (calculated)` = Maximum of (issueObservedDate + 10 days, current date)
    - `issueObservedDate` = `<issueObservedDate in UTC format>`

#### 📌 Key Guidelines
    - Ensure that `fromDate` or `fromDate (calculated)` is provided.
    - Ensure that `toDate` or `toDate (calculated)` is provided.
    - Ensure the time range between fromDate and toDate is not more than 30 days.
    - Ensure the issue time is not older than 4 months from the current time and clearly highlight if it is older than 4 months.
    - Use `GetCurrentUtcTime` tool to get the current time in UTC format.

### 🔹 Step 3: Fetch the Container App Resource(s)
- **Purpose:**
    - Retrieve the details of the container app resources for each subscription ID.

- **How to proceed:**
    For each subscription ID, provide the following details:

    ### Subscription ID - <Subscription ID>

    - **Subscription ID**: `<Subscription ID>`
    - **Resource Group Name**: `<Extracted from /resourceGroups/<ResourceGroupName> pattern>`
    - **Managed Environment Name**: `<Fully Qualified Azure ARM Resource ID of Managed Environment pattern: /subscriptions/<SubscriptionID/resourceGroups/<ResourceGroupName>/providers/Microsoft.App/managedEnvironments/<ManagedEnvironmentName>>`
    - **Container App Name**: `<Fully Qualified Azure ARM Resource ID of Container App> pattern: /subscriptions/<SubscriptionID>/resourceGroups/<ResourceGroupName>/providers/Microsoft.App/containerApps/<ContainerAppName>`
    - **Container App Job Name**: `<Fully Qualified Azure ARM Resource ID of Container App Job> pattern: /subscriptions/<SubscriptionID>/resourceGroups/<ResourceGroupName>/providers/Microsoft.App/jobs/<ContainerAppJobName>`
    - **Container App Session Pool Name**: `<Fully Qualified Azure ARM Resource ID of Container App Session Pool> pattern: /subscriptions/<SubscriptionID>/resourceGroups/<ResourceGroupName>/providers/Microsoft.App/sessionPools/<ContainerAppSessionPoolName>`

    Additionally, extract and list any mentioned child resources under the following parent resources:

    - `Microsoft.App/managedEnvironments`
    - `Microsoft.App/containerApps`
    - `Microsoft.App/jobs`
    - `Microsoft.App/sessionPools`

    For each child resource:

    - **<Child Resource Type>**: `<Fully Qualified Azure ARM Resource ID of the child resource>`

#### 📌 Key Guidelines
    - Don't show resource IDs which are not provided.

### 🔹 Step 4: Return final detailed report with defined template
Your task is to:

- **Extract all relevant information** from the provided incident.
- **Format the extracted information** into a well-structured Markdown document, adhering strictly to the specified template.
- **Ensure no information is omitted**. If certain details do not fit into predefined categories, include them under the `Additional Information` section.

### 📌 Key Guidelines

- **Completeness**: Do not omit any information present in the ICM.
- **Clarity**: Ensure the Markdown is well-formatted and easy to read.
- **Structure**: Use only `##` headings as primary headings.
- **Emphasis**: Utilize bold text and emojis where appropriate to enhance readability.
- **Date Formats**: Use UTC format for all dates and times.
- **Compact**: Keep the response concise and compact without having unnecessary new line or white spaces.

## Investigation Approach
1. **Check Image Pulling Status**: Use the check_image_pulling tool to check the image pull status. If the image pull did not succeed, proceed to the next step. Otherwise, end the investigation and mark the plan as complete using the MarkPlanComplete tool.
2. **Verify Existence, Authentication and Connectivity**:
   - Notify the user that you're now checking registry existence, authentication and connectivity to ensure their app can access the image.
   - Check Image Existence: Verify the specified image exists in the registry with the correct tag and if it is accessible. Check for image tag problems (non-existent tags, malformed paths)
   - Determine the Registry Type: Identify whether the Linux Web app or Container App is using Azure Container Registry (ACR) or an external registry like Docker Hub
   - For Images in Azure Container Registries: Check Managed Identity configuration, verify ACR-Pull role assignments, and test connectivity between the app and the registry
   - For Images in External Registries: Check for rate limiting, network connectivity, and authentication configuration
   - Analyze Network Security: Examine NSG rules that might be blocking connectivity to the registry and validate access to registry endpoints (ACR or external)
    - If misconfiguration is found, recommend specific rule changes and provide a diagram or table summarizing blocked ports/IPs
3. **Recommend Specific Fixes**: 
  - Offer clear, actionable remediation steps tailored to the identified issues and context of the user's resource. 
  - Include relevant links to Azure documentation or other helpful resources.
  - Present findings and recommendations in a well-structured HTML document.
  - Include tables and/or graphs to visualize the log data if applicable.
  - Use Markdown for formatting data to make it readable.
  - If no image pull failures are detected, inform the user that this specific issue has been ruled out.
4. **Offer Next Steps or Fallback Options**:
  - If the issue persists and cannot be resolved automatically, prompt user using AskUserForInput and ask them if they would like you to carry out the following actions. Only propose the following actions ifg they are applicable to their issue
   - Update container images to new working versions using the UpdateContainerImage tool
   - Roll back to the last known working image
   - Retry pulling the image using the RetryImagePull tool
   - Exit investigation
5. **Rollback (Only on User Confirmation)**:
    - If the user consents, use NotifyUser tool to notify the user that you're rolling back their app to the last working image and this may cause a brief restart.
        - Use the RollbackToLastWorkingImage tool to roll back to the last working image
        - Notify the user once completed
    - If the user declines, let them know that rollback was not performed and use the MarkPlanComplete to mark the plan as complete
6.  **Final Summary & Completion**:
    - Use NotifyUser tool to present a final summary of the investigation in the following format and ensure it is well-formatted:
        - Issue: [Detected issue]
        - Actions Taken: [e.g., “Verified ACR auth”, “Rolled back image”, etc.]
        - Next Steps: [If any]
    - Then use MarkPlanComplete tool to mark the plan as complete

## Common Issues and Resolutions
- **Image Not Found (404)**: Verify image tag exists, check repository spelling
- **Authentication Failures**: Update credentials, check registry permissions
- **Missing or Improperly Configured Managed Identity**: Enable System-Assigned Managed Identity and grant ACR-Pull role
- **Network Security Group Blocking Access**: Identify and recommend changes to NSG rules to allow outbound traffic to registries
- **Rate Limiting**: Implement pull strategies with retry logic, use ACR or Managed Identity
- **Network Connectivity**: Check firewall rules, private endpoints, network configuration
- **Malformed Image References**: Correct syntax for image references

## Best Practices to Recommend
- Use specific image tags instead of 'latest'
- Implement proper authentication (Managed Identity for ACR instead of Service Principal or admin credentials)
- Set up retry mechanisms for transient failures
- Implement proper monitoring and alerting
- Use Azure Private Link for secure registry access
- Configure proper logging for container operations

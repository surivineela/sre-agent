# SRE Agent Kusto Tables Reference Guide

This document provides a comprehensive reference for all Kusto tables in the SRE Agent telemetry database.

## Database Information

| Property | Value |
|----------|-------|
| **Cluster URIs** | `https://sreagent-bn.eastus2.kusto.windows.net/` (East US 2) |
|  | `https://sreagent-sec.swedencentral.kusto.windows.net/` (Sweden Central) |
|  | `https://sreagent-sy.australiaeast.kusto.windows.net/` (Australia East) |
| **Database** | `sreagent` |

## Functions

Before diving into the tables, note that the database provides several helper functions:

| Function | Description |
|----------|-------------|
| `All(tablename)` | Universal table accessor that allows querying any table by name as a string parameter |
| `ExtendedAgentDocumentDBState()` | Enriched version of `AgentDocumentDBState` with additional customer metadata (CustomerName, CustomerCategory, ServiceGroupName) |
| `TransformSessionCliEvents()` | Transforms raw session CLI events into structured format |

---

## Table Categories

The tables are organized into the following categories:

1. [Agent Runtime Events](#agent-runtime-events) - Core agent action and behavior telemetry
2. [Resource State Tables](#resource-state-tables) - Database snapshots of Azure resource states
3. [Network & HTTP Events](#network--http-events) - Outbound HTTP requests and API calls
4. [User Feedback](#user-feedback) - Human feedback and satisfaction data
5. [Billing & Token Consumption](#billing--token-consumption) - Usage and cost tracking
6. [Infrastructure Events](#infrastructure-events) - Control plane and admin events
7. [Session & CLI Events](#session--cli-events) - CLI and session proxy events

## Agent Runtime Events

### AgentActionEvents

The **primary telemetry table** for SRE Agent runtime behavior. Contains all significant actions performed by agents including LLM calls, message creation, evaluations, and tool invocations.

| Column | Type | Description |
|--------|------|-------------|
| `PreciseTimeStamp` | datetime | Event timestamp (UTC) |
| `Region` | string | Azure region where the agent is running |
| `AgentName` | string | Unique agent identifier (format: `{name}--{unique-suffix}`) |
| `Action` | string | Type of action performed (see action types below) |
| `Parameter` | string | JSON payload with action-specific parameters |
| `Duration` | int | Action duration in milliseconds |
| `Status` | string | Outcome status (`Success`, `Failure`, etc.) |
| `InputToken` | long | Number of input tokens used (for LLM actions) |
| `OutputToken` | long | Number of output tokens generated (for LLM actions) |
| `CachedToken` | long | Number of tokens served from KV cache |
| `ReasoningToken` | long | Number of reasoning tokens (for o1/o3 models) |
| `ThreadId` | string | Conversation thread identifier |
| `SubAgentName` | string | Name of sub-agent if action was delegated |
| `ThreadSource` | string | Origin of the thread (see ThreadSource values) |
| `FeatureConfig` | string | Active feature flags for the request |
| `ActionMetadata` | string | Additional JSON metadata for the action |
| `ContainerImage` | string | Docker image version running the agent |
| `UpgradeChannel` | string | Deployment channel (stable, preview, etc.) |
| `TraceId` | string | Distributed tracing identifier |
| `SpanId` | string | Span identifier within the trace |
| `ActiveExperiments` | string | Active A/B experiments |

#### Common Action Types

| Action | Description |
|--------|-------------|
| `GenerateModelResponse` | LLM inference call |
| `CreateUserMessage` | User sent a message |
| `CreateAgentMessage` | Agent generated a response |
| `CreateThread` | New conversation thread created |
| `CreateUserInitiatedThread` | User explicitly started a thread |
| `evaluate.thread` | Thread evaluation/scoring completed |
| `evaluate.task` | Task evaluation completed |
| `EvaluateRag` | RAG quality evaluation |
| `ResolveIncident` | Incident resolution action |
| `Heartbeat` | Agent health heartbeat |
| `ExtendedAgent` | Extended agent capability used |
| `ExtendedTool` | Extended tool invocation |
| `ExtendedSkill` | Extended skill execution |
| `IncidentHandlers` | Incident handler configuration |

#### ThreadSource Values

| Value | Description |
|-------|-------------|
| `Conversation` | Regular chat conversations (default) |
| `Incident` | Incident/security related threads |
| `Alert` | Agent invoked by alert or IcM webhook |
| `ScheduledTask` | Agent invoked by scheduled task |
| `DailyReport` | Daily reports generated by DailyReportScanner |
| `BestPractices` | Best practices and security recommendations |
| `WelcomeMessage` | Initial welcome message threads |
| `Playground` | Threads created via configuration playground |
| `Teams` | Agent tagged in Teams channel/chat |
| `Portal` | Legacy type for portal chat (deprecated) |
| `Agent` | Agent proactively created thread |

#### Example Queries

```kql
// Get all LLM calls for a specific agent in the last 24 hours
All('AgentActionEvents')
| where PreciseTimeStamp > ago(24h)
| where AgentName == "my-agent--abc123"
| where Action == "GenerateModelResponse"
| project PreciseTimeStamp, Duration, InputToken, OutputToken, Status

// Calculate success rate by action type
All('AgentActionEvents')
| where PreciseTimeStamp > ago(7d)
| summarize 
    TotalCount = count(),
    SuccessCount = countif(Status == "Success")
    by Action
| extend SuccessRate = round(SuccessCount * 100.0 / TotalCount, 2)
```

## Resource State Tables

These tables contain periodic snapshots of Azure resource states, typically updated every ~2 hours. They are useful for inventory management, churn analysis, and understanding resource lifecycle.

### AgentDocumentDBState

Snapshot of all SRE Agent resources and their configuration. This is the foundational table for agent inventory and metadata.

| Column | Type | Description |
|--------|------|-------------|
| `TIMESTAMP` | datetime | Ingestion timestamp |
| `PreciseTimeStamp` | datetime | Precise event time |
| `Tenant` | string | Azure tenant |
| `Role` | string | Service role |
| `RoleInstance` | string | Instance ID |
| `agentEndpoint` | string | Agent's endpoint URL |
| `agentName` | string | Agent name (without unique suffix) |
| `provisioningState` | string | Provisioning status (`Succeeded`, `Failed`, etc.) |
| `resourceGroup` | string | Resource group name |
| `subscriptionId` | string | Azure subscription ID |
| `dataConnectors` | string | JSON array of configured data connectors |
| `document` | string | Full agent configuration document |
| `buildVersion` | string | Build version |

#### Usage Notes
- Use `ExtendedAgentDocumentDBState()` function for enriched metadata
- Table is updated every ~2 hours; use `bin(PreciseTimeStamp, 2h)` for snapshots
- Join with external customer data using `subscriptionId`

#### Example Query

```kql
// Get all active agents with their data connectors
All('AgentDocumentDBState')
| where PreciseTimeStamp > ago(4h)
| where provisioningState == "Succeeded"
| where isnotempty(agentEndpoint)
| project agentName, agentEndpoint, subscriptionId, resourceGroup, dataConnectors
| take 100
```

Tracks LLM token usage for billing and cost analysis.

| Column | Type | Description |

| `InputTokenUsed` | long | Input tokens consumed |
| `OutputTokenUsed` | long | Output tokens generated |
| `CachedTokenUsed` | long | Tokens served from cache |
| `ReasoningTokenUsed` | long | Reasoning tokens (o1/o3) |
| `ActivityId` | string | Unique activity ID |
| `ContainerImage` | string | Container image |
| `UpgradeChannel` | string | Upgrade channel |
| `ReasoningEffort` | string | Reasoning effort level |
| `TraceId` | string | Trace ID |
| `SpanId` | string | Span ID |

#### Cost Calculation Example

```kql
// Calculate estimated cost per week
All('AgentActionEvents')
| where PreciseTimeStamp > ago(30d)
| where Action == "GenerateModelResponse"
| where Status == "Success"
| extend CustomWeek = bin(PreciseTimeStamp + 3d, 7d) - 3d
| summarize 
    TotalInputTokens = sum(InputToken),
    TotalOutputTokens = sum(OutputToken),
    TotalCachedTokens = sum(CachedToken)
    by CustomWeek
| extend EstimatedCost = 
    ((TotalInputTokens - TotalCachedTokens) * 1.25 / 1000000) +  // Input tokens
    (TotalOutputTokens * 10.0 / 1000000) +                        // Output tokens
    (TotalCachedTokens * 0.125 / 1000000)                         // Cached tokens
```

## Best Practices for Querying

### 1. Use the `All()` Function

The `All()` function provides a consistent interface for accessing all tables:

```kql
All('AgentActionEvents')
| where PreciseTimeStamp > ago(1h)
| take 10
```

### 2. Join with Customer Metadata

Use `ExtendedAgentDocumentDBState()` to enrich events with customer information:

```kql
All('AgentActionEvents')
| where PreciseTimeStamp > ago(7d)
| join kind=leftouter (
    ExtendedAgentDocumentDBState()
    | project AgentName = AgentUniqueName, CustomerCategory, CustomerName, ServiceGroupName
) on AgentName
```

### 3. Week-based Aggregations

Use Friday-based weeks for reporting consistency:

```kql
| extend CustomWeek = bin(PreciseTimeStamp + 3d, 7d) - 3d
```

### 4. Exclude Test Agents

Filter out test and E2E agents:

```kql
| where AgentName !startswith "e2e" and AgentName !startswith "crud"
```

### 5. Filter by Customer Category

Distinguish between FirstParty (Microsoft) and ThirdParty customers:

```kql
| where CustomerCategory in ("FirstParty", "ThirdParty")
```
